# 11. Container With Most Water
difficulty: `medium`
tags: #Array #TwoPointers #Greedy

### Problem
You are given an integer array height of length n. There are n vertical lines drawn such that the two endpoints of the ith line are (i, 0) and (i, height[i]).

Find two lines that together with the x-axis form a container, such that the container contains the most water.

Return the maximum amount of water a container can store.

Notice that you may not slant the container.

```
Example 1:
Input: height = [1,8,6,2,5,4,8,3,7]
Output: 49
Explanation: The above vertical lines are represented by array [1,8,6,2,5,4,8,3,7].
In this case, the max area of water (blue section) the container can contain is 49.
```

Constraints: 2 <= n <= 10^5, 0 <= height[i] <= 10^4

### Note
#two-pointer #array

The brute force is to try every pair, which is O(n²) and will TLE at n = 10^5.

This solves it using two pointers starting at both ends.
At each step, the water area is limited by the shorter of the two walls, so moving the taller pointer inward can never help — it only shrinks the width while the height limit stays the same or gets worse.
So we always move the shorter side inward instead, since that's the only pointer move that could possibly find a taller wall and a larger area.

Why this is safe: area = min(h[left], h[right]) × (right - left). If h[left] < h[right], every pair that uses `left` as one end is already maxed out at the current width, so we can discard `left` without missing a better answer.

帶入範例快速回想：[1,8,6,2,5,4,8,3,7]。left=0(1) right=8(7) → area=1×8=8，left 較矮，left++。left=1(8) right=8(7) → area=7×7=49（就是答案），right 較矮，right--。之後每一步較矮邊都 ≤7 且寬度持續變窄，不可能超過 49，不用逐步再算。

### Solution
```c
int maxArea(int* height, int heightSize) {
    int right = heightSize-1, left = 0;
    int area = 0, best = 0;   // avoid naming a local var the same as the function itself

    while (left < right) {
        if (height[left]<height[right]) {
            area = height[left] * (right-left);   // area is capped by the shorter side
            left++;                               // only ever move the shorter side
        }
        else{
            area = height[right] * (right-left);
            right--;
        }

        best = ( best < area ) ? area : best;
    }

    return best;
}
```

### Complexity — Time / Space:
- Time: O(n) — the two pointers move n steps in total
- Space: O(1)

### Edge Cases:
- n < 2: constraints guarantee n >= 2, so no handling needed — but say this out loud, it earns points
- All bars equal height: answer is the two outermost bars
- Bars of height 0: area is 0, logic still holds
- Overflow: max is 10^4 × 10^5 = 10^9 < INT_MAX. Safe — but do the arithmetic before claiming it's safe

### What the interviewer is listening for
1. Start with the O(n²) brute force and why it TLEs, then optimize. Don't open with the optimal solution.
