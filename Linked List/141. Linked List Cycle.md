# 141. Linked List Cycle
difficulty: `easy`
tags: #HashTable #LinkedList #TwoPointers  #FloydsCycleFindingAlgorithm

### Problem
Given `head`, the head of a linked list, determine if the linked list has a cycle in it.

There is a cycle in a linked list if there is some node in the list that can be reached again by continuously following the `next` pointer. Internally, `pos` is used to denote the index of the node that tail's `next` pointer is connected to. **Note that `pos` is not passed as a parameter**.

Return `true` _if there is a cycle in the linked list_. Otherwise, return `false`.

```
Example 1:
Input: head = [3,2,0,-4], pos = 1
Output: true
Explanation: There is a cycle in the linked list, where the tail connects to the 1st node (0-indexed).
```

### Note
Two people are running on a track, one fast and one slow:

The faster one takes 2 steps each time, and the slower one takes 1 step. Therefore, with a loop, the distance between them decreases by 1 unit each round, and they will inevitably overlap at some point.


Why is the loop condition `fast != NULL && fast->next != NULL`?

`fast == NULL` → the game has reached the end, and taking another step would be a NULL reference, causing a crash.
`fast->next == NULL` → only one unit remains, and a second step cannot be taken; `fast->next->next` will also cause a crash.
Both steps need to be checked; missing one risks a segfault.

### Solution
```c =
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     struct ListNode *next;
 * };
 */
bool hasCycle(struct ListNode *head) {
    struct ListNode* slow = head;
    struct ListNode* fast = head;

    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;          // 1 step
        fast = fast->next->next;    // 2 steps

        if (slow == fast) return true;   // they met -> there's a cycle
    }
    return false;   // fast reached the end -> no cycle
}
```
